    (hidden when it has no visible items) An item matches when, for EVERY facet with a selection, at least one selected value is present on the item: OR within a facet, AND across facets. That is the semantics a CV needs - "control OR autonomy" narrowed by "journal only" - and it is the one thing a taxonomy-as-document-structure cannot express, which is why the topic headings in index.md forced every item into exactly one bucket. WHY THE LIST IS RENDERED SERVER-SIDE AND ONLY *FILTERED* HERE The obvious alternative is to ship JSON and build the list in JS. Not here: this is a CV. The content has to survive with JavaScript off, be indexable, and print. So Liquid renders every item from _data, and this script only sets the `hidden` property. With JS off you get the complete list, which is the correct fallback. {%- endcomment -%}
